# برنامهٔ پیاده‌سازی: چت‌بات فارسی مایلو

**شاخه**: `001-persian-ai-chat` | **تاریخ**: 2026-09-18 | **Spec**: [spec.md](./spec.md)

## خلاصه

یک برنامهٔ وب راست‌به‌چپ برای گفتگوی فارسی ساخته می‌شود که گفتگوها و زمینه را در خود برنامه نگه
می‌دارد و از طریق یک درگاه سمت‌سرور با مدل سازگار با OpenAI ارتباط می‌گیرد. برنامه از جریان پاسخ
متنی برای نمایش وضعیت‌های واقعی تولید استفاده می‌کند، فایل‌ها را پیش از ورود به زمینه به‌صورت امن
اعتبارسنجی و استخراج می‌کند، و ویرایش پیام را با ایجاد شاخهٔ تغییرناپذیر از گفتگو انجام می‌دهد.

## زمینهٔ فنی

**زبان/نسخه**: TypeScript با strict mode؛ Node.js 22 LTS

**وابستگی‌های اصلی**: Next.js با App Router، React، Drizzle ORM، PostgreSQL، Zod، SDK سازگار با
OpenAI، Tailwind CSS، ابزار استخراج متن PDF/DOCX/CSV و Vitest + Playwright

**ذخیره‌سازی**: PostgreSQL برای دادهٔ ساخت‌یافته؛ فضای شیء خصوصی برای فایل خام؛ متن استخراج‌شده و
فراداده در پایگاه‌داده. آداپتر فضای شیء محلی فقط برای توسعه مجاز است.

**آزمون**: Vitest برای قراردادها و منطق قطعی؛ آزمون یکپارچه با PostgreSQL و ارائه‌دهندهٔ شبیه‌سازی‌شده؛
Playwright برای جریان‌های مرورگر و دسترس‌پذیری.

**سکوی هدف**: وب مدرن دسکتاپ و موبایل، با مرورگرهای به‌روز و راست‌به‌چپ.

**نوع پروژه**: برنامهٔ وب یک‌پارچه با رابط و API سمت‌سرور در یک پروژه.

**اهداف کارایی**: پذیرش پیام و وضعیت اولیه کمتر از 1 ثانیه؛ آغاز پاسخ کمتر از 10 ثانیه و تکمیل پاسخ
معمول کمتر از 60 ثانیه، مشروط به عملکرد ارائه‌دهنده.

**محدودیت‌ها**: حداکثر 3 فایل و 10 مگابایت برای هر فایل، حداکثر 20 مگابایت در هر پیام؛ فقط PDF،
DOCX، TXT، MD و CSV؛ حداکثر 20 هزار توکن برای کل زمینه؛ کلیدها فقط سمت‌سرور.

**مقیاس/دامنه**: MVP برای فضای کاری شخصی با حدود 100 کاربر فعال هم‌زمان؛ اشتراک‌گذاری گروهی، جستجو،
پوشه و RAG برداری خارج از دامنهٔ نسخهٔ نخست‌اند.

## بررسی قانون اساسی

| اصل | وضعیت | تصمیم طراحی |
| --- | --- | --- |
| فارسی‌محور و دسترس‌پذیر | قبول | `lang=fa`، `dir=rtl`، CSS logical properties، وضعیت‌های aria-live، صفحه‌کلید و آزمون هر دو تم. |
| یکپارچگی گفتگو و دانش | قبول | زمینه فقط از مسیر فعال، فایل‌های آماده و snapshot ارجاع‌های صریح ساخته می‌شود. |
| حریم خصوصی و ایمنی | قبول | اعتبارسنجی/استخراج سمت‌سرور، فضای خصوصی و مالکیت اجباری در هر پرس‌وجو. |
| Next.js و TypeScript ماژولار | قبول | مرزهای مجزای provider، context، persistence، file و UI بدون راز در کلاینت. |
| تعامل تاب‌آور | قبول | رویدادهای جریان فقط برای مرحله‌های واقعی؛ خطاهای فارسی، retry و idempotency. |

تمام دروازه‌ها پس از طراحی نیز قبول‌اند؛ پیچیدگی غیرقابل‌توجیهی ثبت نشد.

## ساختار پروژه

```text
app/
├── (chat)/
│   ├── page.tsx
│   └── chat/[conversationId]/page.tsx
├── api/
│   ├── attachments/route.ts
│   ├── conversations/route.ts
│   ├── conversations/[conversationId]/messages/route.ts
│   └── messages/[messageId]/fork/route.ts
├── layout.tsx
└── globals.css

components/{chat,composer,sidebar,ui}/
lib/{auth,chat,files,model,db,validation}/
drizzle/
tests/{unit,integration,e2e}/
```

**تصمیم ساختار**: یک پروژهٔ Next.js با Route Handlerهای سمت‌سرور انتخاب شد تا اعتبارسنجی فایل،
مجوزدهی، ساخت زمینه و تماس با مدل هرگز به مرورگر واگذار نشود. مرزهای `model`، `files` و `chat` قابل
تعویض‌اند و از وابستگی به یک ارائه‌دهنده جلوگیری می‌کنند.
