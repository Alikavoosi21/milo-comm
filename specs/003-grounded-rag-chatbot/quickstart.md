# راه‌اندازی چت‌بات مبتنی بر منابع

## پیش‌نیازها

- Node.js مطابق نسخهٔ Next.js و package.json پروژه
- برای حالت واقعی: PostgreSQL با افزونهٔ pgvector، سرویس سازگار با OpenAI برای چت و embedding، و کلید Cohere برای rerank
- برای اجرای محلی بدون سرویس بیرونی: `MOCK_AI=true`

## اجرا

1. در مسیر پروژه `npm install` را اجرا کنید.
2. `.env.example` را به `.env` کپی کنید و مقادیر را کامل کنید. رمز ادمین و secret نشست را حتماً تعیین کنید.
3. در حالت واقعی `MOCK_AI=false` بگذارید، `DATABASE_URL`، `AI_*`، `EMBEDDING_*` و `RERANK_*` را تنظیم کنید. اگر سرویس چت embedding هم ارائه می‌کند، `EMBEDDING_BASE_URL` و `EMBEDDING_API_KEY` می‌توانند خالی بمانند؛ مدل embedding باید واقعاً در آن endpoint موجود باشد.
4. `npm run db:migrate` را برای schema برنامه اجرا کنید. مسیر RAG نیز در زمان نخستین استفاده افزونهٔ vector و جدول‌های خودش را با `CREATE IF NOT EXISTS` آماده می‌کند. کاربر پایگاه‌داده باید اجازهٔ نصب افزونهٔ vector را داشته باشد.
5. `npm run dev` را اجرا کنید؛ وارد `/admin` شوید و با رمز ادمین تا سه فایل PDF، DOCX، TXT، MD یا CSV، هر کدام تا ۱۰ مگابایت، بارگذاری کنید.
6. پس از وضعیت «آماده»، در صفحهٔ اصلی پرسش بپرسید. پاسخ مستند نام منبع را نشان می‌دهد. برای سؤال بی‌شاهد، متن ثابتِ مشخصات نمایش داده می‌شود.

در `MOCK_AI=true` جست‌وجوی واژگانی محلی و پاسخِ برشی از متن منبع به کار می‌رود. این حالت برای دیدن جریان برنامه و آزمون است؛ ارزیابی کیفیت RAG واقعی باید با providerها انجام شود.

## جریان داده

برای PDF دارای لایهٔ متن، بارگذار سند LangChain همهٔ صفحه‌ها را جداگانه می‌خواند و شمارهٔ صفحه را در metadata نگه می‌دارد. PDF تصویریِ بدون متن قابل استخراج به‌جای ثبت ناقص با پیام نیاز به OCR رد می‌شود. متن بیش از ۲٬۰۰۰٬۰۰۰ نویسه نیز با پیام تقسیم فایل رد می‌شود. پس از تغییر این مسیر، PDFهای قبلاً ثبت‌شده را در پنل جایگزین کنید تا دوباره قطعه‌بندی شوند.

فایل ادمین استخراج می‌شود، با `RecursiveCharacterTextSplitter` به قطعه‌های ۱۰۰۰ نویسه‌ای با هم‌پوشانی ۱۵ نویسه تقسیم می‌شود و embedding آن در `PGVectorStore` ذخیره می‌شود. برای هر پرسش حداکثر ۱۲ نامزد بازیابی می‌شود؛ `CohereRerank` چهار قطعهٔ برتر را برمی‌گرداند. فقط نسخهٔ فعال منابع در بازیابی شرکت می‌کند. مدل چت با `temperature=0` صرفاً نقل‌قول‌های قابل تطبیق با همین قطعه‌ها را برمی‌گرداند و citation از metadata سرور ساخته می‌شود. اگر شاهد معتبر نباشد، پاسخ ثابتِ بی‌منبع نمایش داده می‌شود.

حافظهٔ کوتاه‌مدت برای هر گفتگو جداست. وقتی context فعال از آستانهٔ `MEMORY_ACTIVE_TOKEN_LIMIT` بگذرد، پیام‌های قدیمی خلاصه و هشت پیام آخر در context فعال حفظ می‌شوند. متن کامل گفتگو در transcript باقی می‌ماند و خلاصه هرگز به‌عنوان شاهد RAG استفاده نمی‌شود.

گزارش `/admin/usage` عملیات answer، summarize، embed و rerank را با تعداد token، وضعیت و هزینه نمایش می‌دهد. برای embedding و rerank تعداد token تخمینی است؛ هزینه فقط وقتی نرخ‌های اختیاری env تعریف شده باشند محاسبه می‌شود. متن پرسش، پاسخ و فایل در رخداد مصرف ذخیره نمی‌شود.

## استقرار و تنظیم کیفیت

`.data` و `STORAGE_DIR` در حالت محلی روی دیسک همان نمونه ذخیره می‌شوند. برای چند نمونهٔ هم‌زمان باید این فضای ذخیره‌سازی و state گفتگوها به زیرساخت مشترک منتقل شود. حالت واقعی RAG منابع و مصرف را در PostgreSQL نگه می‌دارد، اما فایل‌ها همچنان در `STORAGE_DIR` هستند.

`RAG_CANDIDATES` پیش‌فرض ۱۲ و `RAG_MIN_SCORE` پیش‌فرض ۰٫۳۵ است. این امتیاز با provider و مدل rerank تغییر می‌کند؛ آن را با پرسش‌های دارای پاسخ و بی‌پاسخ از سه منبع واقعی تنظیم کنید. برای سنجش، پاسخ مستند، citation، سؤال خارج از منبع، تزریق دستور در فایل و پیوستگی گفتگو پس از خلاصه‌سازی را بررسی کنید.

## کنترل‌های توسعه

- `npm run typecheck`
- `npm run lint`
- `npm test`
- `npm run build`
- `npm run test:e2e`

آزمون‌های خودکار از provider محلی استفاده می‌کنند و به کلید واقعی نیاز ندارند. تنظیم و اتصال providerهای واقعی باید با credentials و پایگاه‌دادهٔ محیط مقصد بررسی شود.



### وضعیت مدل و ذخیره‌سازی

`MOCK_AI=true` پاسخ محلی آزمایشی می‌دهد، حتی اگر `AI_API_KEY` تنظیم شده باشد. `RAG_STORAGE_MODE=local` منابع و رخداد مصرف را محلی نگه می‌دارد؛ مقدار `pgvector` از PostgreSQL استفاده می‌کند. تغییر `MOCK_AI=false` باعث ارسال پرسش، خلاصهٔ گفتگو و قطعه‌های بازیابی‌شده به endpoint تنظیم‌شده در `AI_BASE_URL` می‌شود و نیاز به تأیید مالک داده‌ها دارد.

پیام‌های اجتماعی کوتاه با قاعدهٔ ثابت پاسخ می‌گیرند. پیام‌های سؤال‌دار یا درخواست گفتگوی باز به مسیر RAG می‌روند؛ پاسخ خارج از منبع همچنان fallback ثابت است.

### PDF و مدل واقعی

اگر لایهٔ متن PDF حروف جدا و تکراری برگرداند، فایل پیش از ثبت منبع با پیام مشخص رد می‌شود. قابل انتخاب بودن متن در نمایشگر PDF به معنی سالم بودن لایهٔ متن برای استخراج نیست؛ چنین فایل‌هایی باید با OCR فارسی دوباره به PDF جست‌وجوپذیر تبدیل شوند. این نسخه OCR داخلی ندارد.

مدل واقعی باید `temperature=0` را بپذیرد. در AvalAI مدل `gpt-5.6-luna` این تنظیم را با HTTP 400 رد کرد؛ `gpt-4o-mini` با همین تنظیم پاسخ داد. نام مدل را در `AI_MODEL` تعیین کنید.

### جست‌وجوی معنایی و فهرست منابع در چت

در `RAG_STORAGE_MODE=local` و `MOCK_AI=false` قطعه‌ها با LangChain و مدل `EMBEDDING_MODEL` بردارسازی می‌شوند؛ برای AvalAI اندازهٔ هر درخواست embedding یک متن است. بردارهای منبع‌های قدیمی در نخستین بازیابی تکمیل و در فایل محلی ذخیره می‌شوند. در `MOCK_AI=true` بازیابی واژگانی آزمایشی باقی می‌ماند.

دکمهٔ ذره‌بین در کادر پیام، پنجرهٔ کوچکی با نام منابع آماده باز می‌کند و از همان‌جا می‌توان فایل مخصوص همان پیام را پیوست کرد. فهرست فقط نام منابع فعال را نشان می‌دهد.
